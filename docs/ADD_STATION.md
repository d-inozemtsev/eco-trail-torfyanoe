# Открытие и добавление станций

Движок автоматически находит файлы `app/stations/station_*.py`. Каждый экспортирует **один словарь `STATION`**. Порядок определяется полем `number`, а идентичность — `id`. Данные доступны через `/api/route`; интерфейс строится из них.

Для открытия станции 2, 4, 6, 7 или 9 замени содержимое существующего файла, сохранив её `id`, номер и при необходимости координаты. Поставь `status: 'active'` и добавь блоки. Для новой точки создай следующий файл.

## Минимальный полноценный пример

Сохрани как `app/stations/station_11.py`. Это демонстрация формата; координаты и содержание перед публикацией надо выбрать для реальной точки.

## Контракт данных

- `id` станции и блока: строчные латинские буквы, цифры, дефисы; начинать с буквы. Они должны быть уникальны внутри своего уровня.
- `number`: уникальное положительное целое число.
- `coordinates`: `[широта, долгота]` в градусах.
- `status`: `active` или `locked`.
- `blocks`: непустой список для активной станции.
- Все блоки, кроме последнего, указывают `next_block_id` следующего блока в списке. Последний показывает завершение станции.
- `completion`: `title` и `text` для экрана завершения.
- `sources`: необязательный список `{title, url}` с проверяемыми источниками.
- Тексты — обычные строки. HTML в текстах экранируется. Структуру статьи задавай через `content`.

## Готовые механики

| `type` | Назначение | Основные поля |
|---|---|---|
| `checklist` | Несколько наблюдений, отсутствие находок допустимо | `options`; опционально `timer: 60`, `photo: True` |
| `story` | Статья и смысловые выноски | `opening`, `content` с `paragraph` и `fact` |
| `choice` | Выбор с объяснением компромиссов и баллами характера | `options`: `gain`, `risk`, `best_for`, `scores` |
| `profile_choice` | Одна личная симпатия | `options`: `title`, `summary`, `scores` |
| `observation` | Выбор одного наблюдения | `levels`, `question`, `answers`, `feedback` |
| `visual_quiz` | Несколько природных прототипов среди рисунков | `options`: `is_real`, `answer_text`; рисунки текущего шаблона — четыре микрожителя |
| `true_false` | Утверждения с немедленным объяснением | `questions`: `text`, `answer` (bool), `explanation` |
| `ship_builder` | Учебный конструктор | `parts`, `slots`, `physics`, `solution`; см. станцию 8 |

Для фотоохоты `options[].image` сейчас выбирает справочную карточку `pine`, `spruce`, `fir` или `juniper`. Без этого поля остаётся обычная карточка наблюдения. Фото участника работают при `photo: True` независимо от справочной картинки.

Веса `scores` используют только `guardian`, `explorer`, `observer`, `strategist`, `connector`; допустимы неотрицательные числа до 10. Рекомендуемый основной вес — 3, дополнительный — 1. Научным вопросам не назначай личностные баллы.

Валидация при запуске обнаруживает повторяющиеся ID, номера, неверные переходы, неизвестные механики и неправильные баллы. Локальные файлы станций исполняются как Python: это контент доверенного редактора, не пользовательские загрузки.

## Что действительно не требует правок движка

Тексты, порядок станций, новые станции из готовых блоков, варианты ответов, баллы, координаты, количество вопросов «правда/ложь» и состав наблюдений. Финальный образ считается по всем текущим вопросам, а финал требует завершения всех **активных** станций.

Принципиально новая игра, другой визуальный набор для микровикторины или новые итоговые персонажи потребуют маленького расширения соответствующего рендерера/`TRAITS`. Добавление такой логики не маскируется под простую правку текста.

После обновления контента:

```bash
python3 -m pytest -q
node --test tests/core.test.js
```

Тесты читают реальные файлы станций, а не отдельную копию контента. При изменении количества станций обнови ожидаемый состав в API-тесте и сценарий мобильного регрессионного прогона.
